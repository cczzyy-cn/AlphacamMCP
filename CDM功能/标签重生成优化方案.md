> - 仍**未**落地：方案 C（增量重生成 `sOnlySheet`/`lngOnlyPart`）、D.2（材料名由入口直接传参）、
>   D.4（临时文件用 `GetTempName`/GUID 独立子目录）、D.1 之外的逐件 `SaveEmfFile` 结果校验。

> ## ✅ 最终落地状态（2026-09-02，v2.1 / 已部署运行工程）
> - **结论**：`g_RegenDoorLabelEMFs` = **m_Create-based 方案**（正确产出件号 EMF）+ **事务同步数据库（AD_REPORT_DATA）** + **`App.OpenDrawing` 重开原档案**。重生成标签会**刷新标签图片并同步数据库**。
> - 已解决的三类问题：① 主图不再被写坏（m_Create 走 `sNestARDOverride` 临时嵌套路径，绝不覆盖用户主图）；② 不再闪退（移除了对主图做 `Name`/`Kill` 的 park/restore）；③ 标签 EMF 正常产出（`<Job>_<材料>_<板>_<件号>.emf` 在图片目录），BarTender 可取图。
> - 数据库同步：按 `DEF_ATT_DETAIL_ID` 事务更新 `AD_REPORT_DATA.PressDoorImage/PressDoorCounter`，并删除已删板件记录。
> - 重生成后用 **AlphaCAM 打开档案 API `App.OpenDrawing`** 重开用户原档案，并 `ZoomAll` 刷新视图。
> - 已知小遗留：m_Create 方案生成时仍会开一个临时 `regen_*` 窗口（方案固有），用完手动关闭即可；不影响真档案/标签。
> - 备份：代码快照 + `backup_cdm_arb.py`（详见下述）。
> - 探索过的“无窗口重生成”（`App.OpenTempDrawing`+`CreateTempDrawing`+直接 `SaveEmfFile`）**已实测原语可行**，但端到端未产出件号 EMF，故未采用（`m_RegenDoorLabelsViaTempCopy` 已随回退移除）。

> **历史落地记录（P0、P1）**：
> - **P0**（`modAutoImportNest.g_RegenDoorLabelEMFs`）：① 旧 EMF 由“先 `Kill` 删除”改为“先`Move`到备份目录、

>   ④ 备份目录时间戳命名。部署前运行模块与磁盘备份确认只差大小写/空行。
> - **P1**（`Make.bas`）：把 `m_CreateAlphaCAMDrawingsOfSheets` 内联的“逐件高亮+导出 EMF”提取为共享例程
>   `m_ExportDoorLabelEMFs(sMatName, sSheetName)`，生产与 `g_RegenDoorLabelEMFs`（经由 `m_Create…`）共用，
>   行为保持(behavior-preserving)；`Make.bas` 备份 `backup/Make_running_before_p1.bas`。
> - **⚠ 待回归**：P1 触碰生产排版逻辑，下次真实生产前请在 AlphaCAM 跑一次排版核对标签输出与之前一致。

## 一、现状流程（做了什么）

```
cmdRegenLabel_Click
  └─ g_RegenDoorLabelEMFs
      0. 校验当前图是排版档案（GetNestInformation，先判 Nothing 再取 Sheets.Count，规避 Or 不短路）
      1. 从 ToolPaths 的 DEF_ATT_JOB_NAME 恢复订单名
      2. 三级回退恢复材料名：图纸名 → AD_REPORT_DATA.PressDoorImage 路径 → 明细表 Material → 图纸属性
      3. 连库 + m_PopulateNestingZones（填充模块级 pthsNestZones）
      4. SaveAs 当前用户图 → 临时副本 sTmpBak
      5.1 删除旧 <Job>_<Mat>_*.emf（Dir$/Kill 循环）
      5.2 App.New → OpenDrawing sTmpBak → 直接复用 m_CreateAlphaCAMDrawingsOfSheets
      5.3 遍历 Nest.Sheets/Parts/Paths，按 DEF_ATT_DETAIL_ID 更新 AD_REPORT_DATA.PressDoorImage/PressDoorCounter，
          并删除已不存在详情的记录
      5.4 重开临时副本 → SaveAs 回用户正式文件 → 删临时文件
```

`m_CreateAlphaCAMDrawingsOfSheets` 内部（标签相关部分）：
1. 遍历 Nest，给每个 Npi.Paths 写 `DEF_ATT_NEST_DOOR_COUNT`（=lngPartCount，按板递增）。
2. `ActiveDrawing.SaveAs strSave` 存嵌套 ARD（strSave = 编译的嵌套 ARD 路径）。
3. 每板 `CreateTempDrawing` → 拆分几何 → `SaveAs <Job>_<Mat>_<板名>.ard`。
4. 背景设为白、关渐变、按板打开 → 整板 `SaveEmfFile <板名>.emf`。
5. 逐件：当前件红色+阴影 hatched、其余浅灰 → 逐件 `SaveEmfFile <板名>_<件号>.emf`。
6. 结尾恢复背景色，`OpenDrawing strSave` 还原嵌套图。

## 二、核心问题

| # | 问题 | 影响 | 严重度 |
|---|------|------|--------|
| 1 | **复用 400 行生产巨型例程**：标签只是它的一段副产物；为“重生成标签”跑一遍完整拆分/保存/背景/复制流程 | 慢、副作用多、逻辑耦合，任何一处改动都可能连带破坏生产排版 | 高 |
| 2 | **无原子性/失败回滚**：`5.1` 先把全部旧 EMF `Kill` 删除，若后续任一步失败，旧标签已丢且 `On Error GoTo EH` 只弹框+记日志 | 标签丢失，用户无图上图可用 | 高 |
| 3 | **绘图窗口/文件大量读写副作用**：`SaveAs strSave`、`CreateTempDrawing`、`OpenDrawing strSave` 全在共享的 AlphaCAM 会话里做；用户正式嵌套 ARD 可能被 `SaveAs` 覆盖到另一路径 | 与用户当前打开图状态冲突，易“跳图”/误存 | 高 |
| 4 | **DB 同步循环有隐患**：`For Each p In Npi.Paths … If 属性… Then 更新… Exit For` ——只处理**第一个**带属性的 Path，多路径板件会漏；且以 `DEF_ATT_NEST_DOOR_COUNT` 为新件号，一旦属性陈旧则文件路径映射错 | 标签路径/件号与磁盘文件不一致 | 中 |
| 5 | **回退猜材料**：图纸名/路径/明细/属性拼出的材料名在“多材料、文件名含下划线、路径含订单名”时易误判（`Mid$/Left$` 硬切） | 材料不对 → EMF/缩略名/barcode 全链路错误 | 中 |
| 6 | **只能全量重生成**：无论如何都必须重跑所有板、所有件的导出；用户只是挪了一扇门也要全量重算 | 大板/多板订单耗时明显 | 中 |
| 7 | **缺中间状态/进度可观性**：`SaveEmfFile` 结果未校验（返回/阻塞），无每个件/板的日志粒度 | 出错定位困难 | 低 |
| 8 | **临时副本取名用 `Format$(Timer,"0")`** 且放公共数据目录，多实例/并发时可能撞名、残留 | 偶发冲突/脏文件 | 低 |

## 三、更好的方案

### 总思路：把“标签导出”从生产流水线里**解耦成一个独立、原子、只做工的例程**，生产与重生成共用它（单一事实来源），并给整段加重做区备份/回滚。

#### 方案 A（推荐）：抽出独立 `m_ExportDoorLabelEMFs`，生产与重生成共用

在 `Make.bas` 新增一个**纯导出例程**，只负责“当前嵌套图 → 逐件高亮 EMF”，`m_CreateAlphaCAMDrawingsOfSheets` 的标签阶段与 `g_RegenDoorLabelEMFs` 都调用它：

```vba
' 单板导出全部件标签；bIncremental=True 且 sOnlySheet 非空时只导出该板
Private Sub m_ExportDoorLabelEMFs(ByVal Material As CMaterial, _
                                  Optional ByVal sOnlySheet As String = "")
    ' 前置：ActiveDrawing 已是待导出嵌套图；背景已设为白；分区已隐藏
    Dim SH As NestSheet, Npi As NestPartInstance, p As Path
    Dim nInfo As NestInformation
    Set nInfo = ActiveDrawing.GetNestInformation
    For Each SH In nInfo.Sheets
        If sOnlySheet <> "" And UCase$(SH.Name) <> UCase$(sOnlySheet) Then GoTo NextSheet
        Dim lngPartCount As Long: lngPartCount = 0
        For Each Npi In SH.Parts
            lngPartCount = lngPartCount + 1
            ' 当前件红+阴影、其余浅灰（沿用现有高亮逻辑，此处从略）
            Call m_HighlightPartAndExport(SH.Name, lngPartCount, Material)
        Next Npi
NextSheet:
    Next SH
End Sub
```

- 生产路径：`m_CreateAlphaCAMDrawingsOfSheets` 内部把那段“逐件高亮 + SaveEmfFile”替换成 `Call m_ExportDoorLabelEMFs(Material)`。
- 重生成路径：`g_RegenDoorLabelEMFs` 只做“**备份旧 EMF → 打开副本 → m_ExportDoorLabelEMFs → 同步 DB → 还原**”，不再触发整段拆分/保存/还原。

收益：**一份标签逻辑**，避免生产与重生成漂移（这是当前最大的隐患）。

#### 方案 B：原子性 + 失败回滚（重生成必做）

把 5.1 的“先删旧”改成“**先备份、后生成、成功才提交**”：

```vba
' 备份目录：<公共目录>\regen_backup_<Job>_<Mat>_<随机>
sBakDir = gs_GetCommonAppDataDir & "regen_backup_" & gstr_JobName & "_" & sMat & "_" & Format$(Timer, "0") & "\"
MkDir sBakDir
' 1) 把旧 <Job>_<Mat>_*.emf 移动到 sBakDir（Move，而非 Kill）
' 2) 生成新 EMF
' 3) 成功 → 删除 sBakDir
' 4) 任一失败 → 把 sBakDir 里的旧 EMF 拷回原位，再报错
```

关键：成功前**绝不删除/覆盖旧产物**。数据库同步同理：先在一个未提交事务里 `UPDATE`，全部成功才 `COMMIT`。

#### 方案 C：增量重生成（大板提速）

- 窗体增加“选中门板”的入口：`g_RegenDoorLabelEMFs` 支持 `Optional sOnlySheet` / `Optional lngOnlyPart`。
- 用户仅挪了某板某件时，只导出一张 EMF、只更新对应 `AD_REPORT_DATA` 行，其余不动。
- 也可基于选中件定位：`ActiveDrawing.GetSelectedPaths` 取高亮件的 `DEF_ATT_NEST_DOOR_COUNT` / `DEF_ATT_DETAIL_ID`，只重导该件。
- 全量/增量两种模式都走同一导出例程，只在“导出集合/DB 更新集合”上做裁剪。

#### 方案 D：健壮性修补（无论是否重构都建议）

1. **DB 同步去掉 `Exit For`**：一个 DetailID 的所有 Path 都更新，不再只取第一条。
2. **材料名解析改为参数直传**：把 `sMat` 作为 `g_RegenDoorLabelEMFs` 的 `Optional` 参数，最好由重生成入口直接带进来（窗体在排版时已知材料），而不是事后猜——猜是当前最脆弱的一环。若必须解析，统一改用 `InStrRev` 取最后一个 `_`，避免订单名/文件名校名里含 `_` 被硬切。
3. **逐件导出校验**：`SaveEmfFile` 后 `If Len(Dir$(目标&".emf"))=0 Then` 记录失败件号，避免“静默缺图”。
4. **临时文件用 `FileSystemObject.GetTempName` / 加 GUID** 命名，并放独立子目录，避免撞名与残留。
5. **失败恢复现场**：在 `EH` 里把活动图重开为 `sUserARD`（若已被 `SaveAs` 跳走），保证用户图不丢、不跳。

## 四、实施优先级

| 优先级 | 内容 | 理由 |
|---|---|---|
| P0 | 方案 B（备份/回滚 + DB 事务） | 当前会**丢旧标签**，最伤；改动小、见效快 |
| P0 | 方案 D.1（去掉 Exit For 漏更）+ D.4（临时文件名） | 纯正确性修补 |
| P1 | 方案 A（抽出 m_ExportDoorLabelEMFs，生产/重生成共用） | 结构性解耦，消除漂移 |
| P1 | 方案 D.2（材料名由入口直传） | 消除最脆弱一环 |
| P2 | 方案 C（增量重生成） | 性能优化，非必须 |
| P2 | 方案 D.3（逐件结果校验）+ 方案 D.5（现场还原） | 可观测性与兜底 |

## 五、验证要点（重构后）

1. 生产排版 `g_Make_Master` 后标签仍与现在一致（回归，确保抽例程未改变生产行为）。
2. 手动挪一扇门 → 只增量重导该件，其余文件 mtime 不变。
3. 中途制造错误（如断库/只读目录）→ 旧标签完好，且用户当前图纸/文件未被改写。
4. 多板、多材料、订单名/材料名含 `_` 的边界样例。
5. 已删板件对应的 `AD_REPORT_DATA` 记录被正确清理，EMF 无残留。
